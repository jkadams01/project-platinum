# Data contract

The single integration point between the Python asset/data pipeline (`tools/`) and the
Godot runtime (`src/`). **Both sides code against this file.** Changing a shape here is a
breaking change and must be made here first.

All generated JSON lands in `data/` and is committed **only when it contains no
ROM-derived copyrighted content**. Species/move/ability data (from veekun) is committed.
Anything extracted from the owner's ROMs — tilesets, sprites, in-game text, trainer
rosters, encounter tables — is written to `assets/generated/` or `data/rom/`, both
gitignored, and regenerated by `python tools/build_all.py`.

## 1. `data/species.json`  — array, index = national dex number - 1

```jsonc
{
  "id": 25,                       // national dex number, 1..1025
  "name": "Pikachu",
  "types": ["electric"],          // 1 or 2, lowercase
  "stats": {"hp":35,"atk":55,"def":40,"spa":50,"spd":50,"spe":90},
  "abilities": ["static"],        // normal abilities, in slot order
  "hiddenAbility": "lightning-rod", // or null
  "growthRate": "medium-fast",    // erratic|fast|medium-fast|medium-slow|slow|fluctuating
  "baseExp": 112,
  "catchRate": 190,
  "genderRate": 4,                // -1 genderless, else /8 chance female
  "eggGroups": ["field","fairy"],
  "hatchCounter": 10,
  "height": 4, "weight": 60,      // decimetres, hectograms
  "evolvesFrom": 172,             // dex id or null
  "evolutions": [
    {"to": 26, "method": "use-item", "item": "thunder-stone"}
  ],
  "generation": 1,
  "sprite": {"front":"pkmn/025.png","back":"pkmn/back/025.png","icon":"icon/025.png"}
}
```

## 4. `data/abilities.json` — array

```jsonc
{ "id": 9, "name": "Static", "hook": "onContactHit",
  "text": "Contact may paralyze the attacker.", "tier": 1 }
```
`tier`: 1 = engine-implemented, 2 = declared but inert, 3 = data only.

`hook` names the engine seam the ability uses. It is the camelCase image of the
snake_case method on `src/battle/abilities/ability.gd`, which documents each one.
Values, beyond `none`: `onBeforeMove`, `onModifyMoveType`, `onDamageCalc`,
`onEffectiveness`, `onTypeImmunity`, `onWeatherView`, `onMultiHitCount`,
`onProtectCheck`, `onHitTaken`, `onContactHit`, `onAfterHit`, `onFlinch`,
`onSwitchAttempt`, `onFieldEnter`, `onWeatherSet`, `onRedirect`, plus the
pre-existing `onSwitchIn` / `onTurnEnd`.

### 7.1 `data/rom/bosses.json` *(gitignored)*

Boss fights are **not** in `trainers.json`. Every gym leader, Elite Four member, Champion,
Team Galactic boss and rival battle is authored in `bosses.json`, which **overrides** the ROM
record of the same trainer. `romTrainerKey` names the row it replaces.

```jsonc
{
  "schema": "bosses/1",
  "expMultiplier": 2.5,          // mirrors data/level_caps.json
  "megaRule": "one-per-battle",
  "bosses": {
    "fantina": {
      "id": 318, "name": "Fantina", "class": "gym-leader", "badge": "relic",
      "trainerClass": 77, "trainerClassName": "Leader", "ai": 7, "prizeMoney": 4320,
      "order": 7,                  // global progression order, 1..31
      "checkpoint": "fantina",     // the level_caps row this fight IS, else null
      "capIndex": 3, "cap": 36,    // the cap in force DURING the fight
      "location": "Hearthome Gym", "typeTheme": "ghost", "levelRange": "34-36",
      "ace": { "slot": 5, "species": 429, "speciesName": "Mismagius",
               "level": 36, "generation": 4 },
      "megaForm": "gengar-mega",   // the form this boss Mega Evolves into, or null
      "megaSlot": 4,               // party index that carries it, or null
      "awardsStone": "gengarite",  // gym leaders only; a LIST when more than one
      "doublePartner": null,       // the other trainer sharing this enemy side, or null
      "romTrainerKey": "fantina",
      "party": [ /* exactly 6 */
        { "species": 94, "speciesName": "Gengar", "level": 35,
          "moves": ["shadow-ball","sludge-bomb","thunderbolt","dazzling-gleam"],
          "item": "gengarite",       // a Mega member holds its form's stone
          "ability": "cursed-body",  // the PRE-Mega ability
          "abilitySlot": 0,          // 0/1 normal slot, 2 = hidden, null unresolved
          "nature": null,
          "megaEvolves": true,
          "megaForm": "gengar-mega",
          "megaAbilities": ["shadow-tag"]   // from data/megas.json, POST-Mega
        }
      ]
    }
  }
}
```

Invariants the build asserts:

* **Exactly 6 party members** for every boss. Party order is send-out order.
* **`ace` is a Sinnoh-native Gen 4 species** — national dex 387–493, no exceptions. It is the
  fight's centrepiece and the highest level on the team.
* **`ace.level` equals `cap`** for every checkpoint boss, so the player meets it level-matched.
* No party member exceeds the cap in force.
* `megaEvolves` marks the member that Mega Evolves; it is **not** already a Mega at send-out.
  Its `item` is exactly `megas.json[megaForm].stone`, and `megas.json[megaForm].base` is its
  dex id.
* **At most one `megaEvolves` member per boss**, and none before gym 3 (Fantina). In a double
  battle the two trainers are one *side*, so only one of the pair carries a stone —
  `doublePartner` records the pairing.
* `awardsStone` appears on gym leaders only and is the Mega Stone granted on defeat.
* No Dynamax, Gigantamax, Z-Move or Terastal field appears anywhere (§11.4).

Defeating a boss sets `flag:<key>_defeated` (`flag:fantina_defeated`,
`flag:aaron_defeated`, …). §8's Elite Four rows already raise the cap off those flags, and
§12 events condition on them.

`prizeMoney` is null in the ROM dump for every boss. Gym leaders use this section's worked
example — 1680 at ace level 14, i.e. **120 × ace level** — applied to the raised ace level. No
base is known for the other trainer classes, so those stay null.

## 8. `data/level_caps.json`

```jsonc
{ "caps": [
    {"index":0,"checkpoint":"start","cap":18,"raisedBy":null},
    {"index":1,"checkpoint":"roark","location":"Oreburgh Gym","ace":"Cranidos 18","cap":18,"raisedBy":"badge:coal"},
    {"index":2,"checkpoint":"gardenia","location":"Eterna Gym","ace":"Roserade 27","cap":27,"raisedBy":"badge:forest"}
    // ... 15 rows, ending at Cynthia 100
  ],
  "postGameCap": 100,
  "rule": "hard-xp-stop",       // a Pokemon whose level >= current cap gains 0 EXP
  "expMultiplier": null,        // ALWAYS null - see expMultiplierMode below
  "expMultiplierMode": "per-segment"
}
```

**EXP multipliers are PER-SEGMENT, not global.** Each cap row carries its own
`expMultiplier`, applied to all EXP earned while that checkpoint is the active cap.

Why it cannot be one global number: caps are *hard*, so surplus EXP inside a segment is
discarded rather than carried forward. Every segment must therefore independently supply
enough EXP to reach its own cap. Measured against real ROM trainer data, segments 1-5
already run a 1.76-2.58 surplus at 1.0x, while the back half runs as low as 0.39 - so a flat
multiplier large enough to fix the tail caps the player roughly four trainers into the game
and leaves ~50 early battles awarding nothing.

Multipliers are derived as `target_ratio / measured_ratio`, floored at 1.0. Rows also carry
`measuredRatioAt1x`, `targetRatio`, `grindProof` and `expNote` so the derivation stays
auditable.

`grindProof: true` marks the four segments inside the Pokemon League (Bertha, Flint, Lucian,
Cynthia). There the only EXP source is the Elite Four member just defeated - no grass, no
water, no optional trainers, no exit - so a shortfall is **unrecoverable**. Those use a 1.35
target instead of 1.15.

**Engine contract:** `GameState.current_exp_multiplier() -> float` returns the active
segment's multiplier, and `exp.gd` applies it *before* the level-cap check. Never read a
top-level `expMultiplier` - it is permanently `null`.

15 rows, monotonically increasing, terminating at **100**: Cynthia's team is all level 100 and
the curve is built so natural play arrives there. The **active row's** `expMultiplier` is what
makes the raised curve reachable — the battle engine multiplies every exp award by it before
testing the cap, so the cap still wins and a Pokemon at the cap gains exactly 0. Implemented in
`DataRegistry.get_exp_multiplier()` → `GameState.current_exp_multiplier()` →
`src/battle/exp.gd:award()`; asserted in `tests/test_exp_multiplier.gd`. The full table and its
derivation are in `docs/research/level-curve.md`.

    "above":   [[-1,-1,...]]       // drawn above the player
  },
  "collision": [[0,0,1,...]],      // 0 walk, 1 block, 2 ledge-south, 3 water, 4 tall-grass

    {"x":14,"y":9,"type":"smash","requires":"badge:coal"}

**Collision codes** are authoritative:
`0` walkable · `1` blocked · `2` ledge (jump south) · `3` deep water (needs SURF) ·
`4` tall grass (encounters) · `5` shallow water · `6` stairs/climb · `7` waterfall.

## Traversal verbs (HM replacement)

| Verb | Badge | Collision code it clears | Behaviour |
|---|---|---|---|
| `smash` | coal | obstacle object | walk into rock, it shatters, step through |
| `cut` | forest | obstacle object | walk into tree, it falls |
| `fly` | cobble | — | MAP menu entry, visited Centers only |
| `surf` | fen | `3` | mount on shoreline, dismount on land |
| `strength` | mine | obstacle object | push boulder one tile |
| `climb` | icicle | `6` | ascend/descend chevron tiles |
| `waterfall` | beacon | `7` | ascend while surfing |

There is no `defog` verb: fog is removed from the game entirely. The Relic badge grants
the cap raise and story flag only.

## 11. Mega Evolution

**The only battle gimmick in this game.** No Dynamax/Gigantamax, no Z-Moves, no
Terastallization — those are deliberately excluded and must not appear in data or engine
code.

### 11.1 `data/megas.json`

```jsonc
{
  "keyItem": "key-stone",
  "rule": "one-per-battle",       // one Mega Evolution per side per battle
  "revertsAfterBattle": true,
  "forms": [
    {
      "id": "charizard-mega-x",
      "base": 6,                    // national dex id of the base species
      "name": "Mega Charizard X",
      "stone": "charizardite-x",    // item id; must exist in data/items.json
      "types": ["fire", "dragon"],  // may differ from base
      "stats": {"hp":78,"atk":130,"def":111,"spa":130,"spd":85,"spe":100},
      "abilities": ["tough-claws"], // usually one; a few Z-A Megas have two (e.g. Mega Heatran)
      "height": 17, "weight": 1105,
      "introducedIn": "xy",         // xy | oras | za
      "sprite": {"front":"mega/charizard-mega-x.png","back":"mega/back/charizard-mega-x.png",
                 "icon":"mega/icon/charizard-mega-x.png"}
    }
  ]
}
```

A species with two Megas (Charizard, Mewtwo) has two entries sharing `base`; the stone
held decides which. `base` is the dex id, so the runtime resolves
`species.id -> [mega forms]` at load.

### 11.2 Engine contract

- `GameState.has_key_stone() -> bool` — gates the Mega button appearing at all.
- `GameState.mega_unlocked_at` — the story flag/badge that grants the Key Stone.
- `BattleEngine` exposes `can_mega_evolve(pokemon) -> bool`: true when the holder has the
  Key Stone, the Pokémon holds the matching stone, and no Mega has been used this battle
  by that side.
- Mega Evolution resolves **at the start of the turn, before any move**, per the standard
  rule, and the Mega's Speed applies to that same turn's ordering.
- On Mega Evolution: swap types, base stats, ability; recompute stats keeping the current
  HP *fraction*; keep level, moves, PP, status and stat stages.
- Reverts to base form when the battle ends or the Pokémon faints.
- `EventBus.mega_evolved(pokemon, form_id)` fires for UI/animation.

### 11.3 Level-cap interaction

Megas are a large mid-battle stat swing and this game has hard level caps, so the two
systems interact. **Mega Evolution does not change a Pokémon's level and therefore never
affects EXP capping.** The Key Stone is gated behind a story checkpoint chosen in the mega
design doc so that early gyms cannot be trivialised — see `docs/research/mega-design.md`.

### 11.4 Excluded gimmicks — enforced

`tools/build_species.py` and the battle engine must contain **no** Dynamax, Gigantamax,
Z-Move or Terastal data or code paths. If a data source supplies those fields (PokeAPI and
Showdown both do), they are dropped at import. A test asserts their absence.

### 11.5 Exclusions and special cases — DECIDED

**Primal Reversion is OUT.** Primal Groudon and Primal Kyogre are NOT included. They are a
distinct mechanic (Red/Blue Orb, not a Mega Stone) and the owner has excluded them. The
build must assert that neither `primal-groudon` nor `primal-kyogre` appears in
`data/megas.json`, and that no Red Orb / Blue Orb item is emitted.

**Mega Rayquaza is IN, and is the one Mega with no stone.** It Mega Evolves by knowing the
move **Dragon Ascent** while holding no Mega Stone. Its entry uses:

```jsonc
{ "id": "rayquaza-mega", "base": 384, "stone": null,
  "requiresMove": "dragon-ascent", ... }
```

`can_mega_evolve()` must handle `stone == null` by checking `requiresMove` is in the
Pokémon's moveset instead of checking the held item. Because it needs no held stone, it
also bypasses the "holds the matching stone" clause — but still obeys one-Mega-per-side.

**Abilities on Legends Z-A Megas.** Z-A itself has no Ability system, so Z-A Mega forms have
no ability defined in that game. The authoritative source for their abilities is
**Pokémon Champions**. Resolution order for a Z-A Mega's ability:
1. Its ability in Pokémon Champions, if the form appears there.
2. Otherwise, an owner-approved assignment recorded in `docs/research/mega-abilities.md`.

No Z-A Mega may ship with a guessed ability that is not traceable to (1) or (2). A form
awaiting a decision carries `"abilities": []` and `"abilityStatus": "pending-owner"` so it
is visibly unresolved rather than silently wrong.

## 12. `data/events/<name>.json` — overworld story events

A **story event** is a scripted overworld beat: a condition, and an ordered list of things that
happen. One file may hold several events; the overworld loads every file in `data/events/` at
startup and indexes them by `map`.

Events are **hand-authored design data, not ROM-derived, and are committed.**

```jsonc
{
  "schema": "events/1",
  "requiresMapObjects": {          // optional: map id -> object ids the event addresses
    "hearthome_city": ["mega_ring_trigger", "mega_ring_counterpart_spawn"]
  },
  "events": [
    {
      "id": "mega_ring_hearthome",   // unique across all event files
      "name": "The Mega Ring",       // for logs and the debug menu
      "map": "hearthome_city",       // the map id it lives on
      "once": true,                  // fires at most once per save
      "priority": 10,                // higher runs first when two events arm together
      "trigger": { "type": "map-enter", "at": {"mapObject": "mega_ring_trigger"} },
      "requires": [                  // ALL must hold, or the event stays dormant
        {"flag": "fantina_defeated"},
        {"badge": "relic"},
        {"flag": "mega_ring_received", "value": false}
      ],
      "actors": [                    // NPCs the event spawns for its duration
        { "id": "counterpart", "role": "player-counterpart", "sprite": "counterpart",
          "nameToken": "counterpart",
          "spawnAt": {"mapObject": "mega_ring_counterpart_spawn"} }
      ],
      "steps": [ {"op": "lock-player"}, /* ... */ {"op": "unlock-player"} ]
    }
  ]
}
```

### 12.1 Triggers

| `type` | Fires when |
|---|---|
| `map-enter` | the player enters `map` (optionally only on the tile named by `at`) |
| `step-on` | the player steps on the tile named by `at` |
| `talk` | the player talks to the map object named by `at` |
| `flag-set` | the named flag becomes true while the player is on `map` |

`at` is always `{"mapObject": "<object id>"}` and resolves against the `objects` array of
`data/maps/<map>.json` (§9). **Events never carry raw tile coordinates** — the map owns
geometry, the event owns behaviour, so re-authoring a map cannot silently break a script.

### 12.2 Conditions (`requires`)

Every entry is one key plus an optional `value` (default `true`). All entries AND together.

| Form | True when |
|---|---|
| `{"flag": "x"}` / `{"flag": "x", "value": false}` | `GameState.get_flag("x")` matches |
| `{"badge": "relic"}` | `GameState.has_badge("relic")` |
| `{"item": "key-stone", "min": 1}` | the bag holds at least `min` (default 1) |
| `{"capIndex": 3, "op": "gte"}` | `GameState.cap_index` compares true (`gte`/`lte`/`eq`) |

Boss defeats set `flag:<boss key>_defeated` (§7.1), which is how a fight becomes a condition.

### 12.3 Steps

Executed in order. Each is `{"op": "...", ...}`.

| `op` | Fields | Effect |
|---|---|---|
| `lock-player` / `unlock-player` | — | sets `GameState.input_locked` |
| `spawn-actor` / `despawn-actor` | `actor` | adds/removes an entry from `actors` |
| `walk-actor` | `actor`, `to`, `speed` (`walk`\|`run`) | pathfinds to a map object |
| `face` | `actor`, `target` (`player`\|actor id) or `dir` | turns a sprite |
| `emote` | `actor`, `emote` | emotion bubble |
| `dialogue` | `speaker`, `lines[]` | emits `EventBus.dialogue_requested` |
| `give-item` | `item`, `count` | adds to `GameState.bag`; `item` must exist in `data/items.json` |
| `grant-key-stone` | — | calls `GameState.grant_key_stone()` |
| `set-flag` | `flag`, `value` | calls `GameState.set_flag()` |
| `fanfare` | `sound` | one-shot jingle |
| `wait` | `seconds` | pause |
| `battle` | `boss` | starts the `data/rom/bosses.json` fight with that key |

An unknown `op` is a **load-time error**, not a silent skip: a typo must not quietly delete a
story beat.

### 12.4 Dialogue tokens

`lines` are substituted at display time. `speaker` is an actor id, or `"system"` for the
boxed narration voice.

| Token | Expands to |
|---|---|
| `{player}` | `GameState.player_name` |
| `{counterpart}` | the counterpart's name — **Dawn** if the player is Lucas, **Lucas** if the player is Dawn |
| `{rival}` | Barry |

### 12.5 `data/events/mega_ring.json` — the Key Stone handover

The one event this contract names explicitly, because the whole Mega system hangs off it
(§11.3).

* **Giver: the player's NPC counterpart (Dawn/Lucas).** Owner decision. It supersedes
  `docs/research/mega-design.md` §2.4, which had proposed Cynthia; the *checkpoint* is
  unchanged from that document.
* **Where/when: Hearthome City, after Fantina (gym 3).** Conditions are
  `flag:fantina_defeated` + `badge:relic`, which is exactly
  `GameState.mega_unlocked_at = "badge:relic"`.
* **Awards:** the **Mega Ring** — the `key-stone` Key Item, via `grant-key-stone` — plus the
  one usable Mega Stone in the world at that point, `lopunnite` (mega-design.md §2.1).
* **Sets `flag:mega_ring_received`.** The Mega button itself is gated on
  `GameState.has_key_stone() and GameState.mega_unlocked()`, so the grant is what turns it on;
  the flag makes the event idempotent and gives later scripts and the UI tutorial something to
  test without inspecting the bag.
* **Ordering guarantee:** Fantina is the first boss with a `megaForm`, so the player *sees* a
  Mega Evolution in the fight that earns them the Ring. Nothing before gym 3 Mega Evolves, on
  either side.
